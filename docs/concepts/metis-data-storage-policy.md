# Metis データ保存方針

更新日：2026-09-30

本書はデータ保存に関する合意事項を整理したものです。未決定事項と提案は区別して記載します。

## 1. 基本構成

| 保存場所・役割 | 採用する構成 |
|---|---|
| Centralの通信処理 | FastAPI |
| 通信データの検証・モデル | Pydantic |
| Centralの保存モデル・DB操作 | SQLAlchemy |
| Centralの永続保存 | PostgreSQL |
| Agentのローカル永続保存 | SQLite |
| Centralの最新監視値 | メモリに保持。再起動時に全Agentから再取得 |

通信モデルと保存モデルは分けます。通信の一メッセージが、保存先の一行と一致することは前提にしません。

## 2. 保存対象と責任

| 対象 | Agent | Central |
|---|---|---|
| 操作 | 要求の永続受付 | UI要求、転送、受付応答、受付未確認の記録 |
| 警告 | 発報・引き渡し状況の永続記録 | 警告本体、配信待ち、配送試行、acknowledge履歴 |
| 監視 | 観測値・取得状態を提供 | 最新値と観測値履歴 |
| 登録情報 | 操作名・スキーマを提供 | 更新時刻と旧版履歴を保持 |

UIのローカル保存は画面復元の補助とし、共有する記録はCentralで管理します。

## 3. 操作の保存

操作は次の順序で処理します。

1. CentralがUIから受信した操作要求を永続保存する。
2. CentralがAgentへ要求を転送する。
3. Agentが要求をローカルDBへ永続記録し、コミットする。
4. AgentがCentralへ受付完了を返す。
5. Centralが受付状態を永続保存し、UIへHTTP 202を返す。

受付期限内に確認できなければ、Centralは「受付未確認」の記録を保持してHTTP 504を返します。自動再送は行いません。

永続受付は、メモリへの追加だけでは成立しません。要求値への到達や操作成功とは区別します。

## 4. 警告の保存と配送

警告にはoutbox方式を採用します。

- 警告本体と配信待ち記録を、同じDBトランザクションで保存する。
- 保存後、配送処理が配信待ち記録を読み、全UIへの配送を試みる。
- 警告、配送試行、ユーザーのacknowledgeを区別して記録する。
- 警告とacknowledgeの履歴を閲覧可能にする。

配送完了の判定、再試行条件、acknowledgeの更新と履歴追加の具体的なトランザクション設計は、今後詳細化します。

## 5. 監視履歴の保存

観測値は、**変更時保存と一定周期保存を併用**します。

| 条件 | 保存動作 |
|---|---|
| 短い確認周期で変化を検出 | 観測値を保存する |
| 変化なし | 変更時保存をスキップする |
| 定周期保存の時刻に到達 | 変化の有無にかかわらず観測値を保存する |

例として、1秒ごとに変化を確認し、変更時に保存するとともに、1分ごとにも保存します。**1秒・1分は例示値であり、確定値ではありません。**

監視履歴は期限を設けず、永続保存します。履歴保存周期とUIへの配信条件は別です。UIには、既存の通信規格どおり変更値と取得状態を伝えます。

## 6. 保存不能時

- 操作の受付は行わない。
- 情報の配信は継続する。

ただし、保存失敗の発生地点によって扱いを分ける必要があります。

| 発生地点 | 扱い |
|---|---|
| Centralの要求保存に失敗 | Agentへ転送せず、受付しない |
| Agentの永続記録に失敗 | Agentは受付完了を返さない |
| Agent受付後、Centralの受付状態保存に失敗 | Agentの受付済み事実は取り消せない。応答・記録方法は未決定 |
| 警告のoutbox保存に失敗 | 配信は継続する。保存を経由しない配信経路の詳細は未決定 |
| 監視履歴の保存に失敗 | 最新情報の配信は継続する。欠落期間の扱いは未決定 |

## 7. 未決定事項・検討候補

- 監視の確認周期、定周期保存間隔、変化判定方法。
- 定周期保存時に新たな取得を要求するか、最新の取得済み値を保存するか。
- 取得停止中の古い観測値を履歴へ保存する場合の表現。
- 保存障害中に配信する情報への「未保存」表示と、保存障害自体の警告。
- 保存復旧後の未保存情報の補完方法。
- Agent受付後にCentralの保存が失敗した場合のHTTP応答。
- Agent再起動後の受付済み操作の扱い。永続保存だけを理由に自動再実行しない。
- keep-alive全件を保存するか、最新状態と状態変化のみを残すか。
- 操作・警告・配送履歴の保存期間。
- 永続的に増える監視履歴の容量管理とバックアップ方法。

変更時保存と定周期保存が同時に発生した場合、一つの記録で両方を満たす方式は実装候補とします。
